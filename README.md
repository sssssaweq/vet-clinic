# vet-clinic - система учета ветеринарных осмотров
Информационная система для учета животных и ветеринарных осмотров с модулем прогнозирования риска заболеваний.

**Автор:** Гришин Артем Витальевич

## Описание проекта
Информационная система предназначена для учёта ветеринарных осмотров молочных коров и прогнозирования риска заболеваний.<br>
Система хранит информацию о животных, ветеринарах, диагнозах и результатах ветеринарных осмотров. На основе накопленной истории осмотров модуль машинного обучения оценивает риск заболевания: общий и по каждой конкретной болезни (мастит, кетоз, ламинит и т.д.).

## Цель проекта
Разработать информационную систему, которая позволяет:
<ul>
<li>хранить данные о животных и историю ветеринарных осмотров;</li>
<li>учитывать ветеринаров и диагнозы;</li>
<li>анализировать историю состояния животных;</li>
<li>прогнозировать риск заболевания животного и риск конкретной болезни на ближайший период.</li>
</ul>

# 1. Сбор и подготовка данных

Для разработки используется синтетический набор данных.<br>
Сгенерированы данные:<br>
- **400 животных**;
- **10 000 ветеринарных осмотров** (в среднем 25 на животное, период 2023-01-01 — 2025-12-31);
- **10 ветеринаров**;
- **21 диагноз** (20 болезней и «Здоров»), болезни объединены в 5 групп (копыта и конечности; вымя и размножение; обмен веществ и пищеварение; органы дыхания и чувств; инфекции и паразиты).

Данные об осмотрах имеют временную структуру. Для каждого животного существует последовательность осмотров, расположенных в хронологическом порядке.

В данных учитываются:
- возраст животного;
- номер лактации;
- удой;
- оценка хромоты;
- количество предыдущих осмотров;
- количество заболеваний за последние 6 месяцев;
- наличие хронического заболевания;
- дата осмотра;
- диагноз;
- результат осмотра.

**Важно: данные синтетические.** Связи «признак - конкретная болезнь» заданы в генераторе вручную по ветеринарной логике (таблица `DISEASE_RULES` в [src/generate.py](src/generate.py)): например, хромота повышает вероятность ламинита, высокий удой и число лактаций — мастита, зима — бронхопневмонии, возраст — лейкоза. Модель машинного обучения затем проверяет, способна ли она восстановить эти связи по данным. Это проверка работы пайплайна, а не открытие закономерностей на реальных данных. Генератор использует фиксированный seed, поэтому каждый запуск создаёт одинаковые данные.

Генерация данных выполняется с помощью:

# 3. Временная структура данных

Данные об осмотрах формируются с учётом времени.

Для каждого животного осмотры расположены в хронологическом порядке. Это позволяет использовать историю предыдущих осмотров при построении модели прогнозирования.

Принцип работы модели:

**прошлые данные - обучение - проверка на более поздних данных - прогноз следующего периода (2026 год)**

Такой подход позволяет моделировать ситуацию, когда при прогнозировании модель использует только информацию, которая была доступна на соответствующий момент времени.



# 4. Машинное обучение

Модель решает две задачи:

1. **Общий риск:** по истории осмотров животного оценивает вероятность (0–1), что на осмотре будет выявлено заболевание. Если вероятность не ниже порога 0.6 (из ТЗ), животное считается животным с **высоким риском**.
2. **Риск конкретной болезни:** для каждой достаточно частой болезни своя модель оценивает вероятность, что у животного будет выявлена именно эта болезнь.

Модель не ставит диагноз и не заменяет ветеринара: она помогает выбрать, каких животных осмотреть в первую очередь.

Этапы:

1. подготовка данных — **выполнено**;
2. формирование признаков — **выполнено**;
3. разделение данных по времени (70/20/10) — **выполнено**;
4. обучение общей модели и моделей по болезням (логистическая регрессия) — **выполнено**;
5. оценка качества на тестовой выборке — **выполнено**;
6. анализ влияния признаков на разные болезни — **выполнено**;
7. прогноз на 2026 год — **выполнено**;
8. сравнение с другим алгоритмом, интеграция с БД — планируется.

Для оценки качества используются:

- Accuracy — доля верных ответов;
- Precision — из животных, названных больными, доля действительно больных;
- Recall — из действительно больных доля найденных моделью;
- F1-score — совместная оценка Precision и Recall;
- ROC-AUC — насколько хорошо модель ставит больных выше здоровых (0.5 — как случайный выбор, 1.0 — идеально).

Код: [src/train_baseline.py](src/train_baseline.py).

## 4.1. Признаки

| Признак | Смысл |
|---|---|
| `age` | возраст животного, лет |
| `lactation_number` | номер лактации |
| `milk_yield` | удой |
| `lameness_score` | балл хромоты |
| `previous_examinations_count` | сколько осмотров было до этого |
| `diseases_last_6_months` | сколько болезней за последние 6 месяцев |
| `has_chronic_disease` | есть ли хроническое заболевание |
| `previous_sick` | болело ли животное на прошлом осмотре |
| `days_since_last_exam` | дней с прошлого осмотра |
| `is_winter_season` | зимний или переходный сезон (месяцы 11, 12, 1, 2, 3) |

Последние три признака рассчитываются в скрипте по истории осмотров животного, остальные берутся из `examinations.csv`. Диагноз, название болезни и лечение в признаки **не входят**: они известны только после осмотра, и с ними модель «списывала бы ответ» (утечка цели).

## 4.2. Разделение данных

**Разделение 70/20/10 — по времени**, а не случайно: самые ранние осмотры идут в обучение, более поздние — в валидацию и тест. Так модель не «подглядывает» в будущее.

| Выборка | Осмотров | Период | Доля больных |
|---|---|---|---|
| train (обучение) | 7000 | 2023-01-01 — 2025-02-09 | 43.0 % |
| validation (подбор параметров) | 2000 | 2025-02-09 — 2025-09-09 | 53.2 % |
| test (финальная проверка) | 1000 | 2025-09-09 — 2025-12-31 | 60.0 % |

Перед обучением признаки приводятся к одному масштабу (`StandardScaler`). Параметр регуляризации `C` перебирается по списку и выбирается по ROC-AUC на валидации. Тестовая выборка используется один раз, для финальной оценки.

## 4.5. Влияние признаков на разные болезни

Коэффициенты логистической регрессии считаются на стандартизованных признаках, поэтому их можно сравнивать между собой. Красный цвет — признак повышает риск болезни, синий — понижает. Чёрной рамкой обведены связи, заложенные в генераторе.

![Влияние признаков на болезни](models/feature_effects_heatmap.png)

Модель нашла **все 15 заложенных связей**:

| Болезнь | Что повышает риск | Что понижает |
|---|---|---|
| Ламинит, некробактериоз, копытная гниль | хромота (гниль — ещё зима) | |
| Мастит | высокий удой, больше лактаций | |
| Эндометрит, гипокальциемия | больше лактаций | |
| Кетоз, ацидоз рубца | | высокий удой |
| Авитаминоз, бронхопневмония, отит | зима | |
| Паратуберкулёз, лейкоз | возраст | |

Слабое место: влияние зимы на авитаминоз модель почти не видит (коэффициент +0.07), ROC-AUC этой болезни всего 0.57. Остальные коэффициенты — в [models/feature_effects.csv](models/feature_effects.csv), столбчатые графики по каждой болезни — в `models/feature_effects_diseases.png`.

## 4.6. Динамика: как болезнь меняет удой и хромоту

В генераторе после болезни удой падает по-разному: сильнее всего после мастита, кетоза и гипокальциемии, слабее после болезней копыт и дыхания; болезни копыт усиливают хромоту. Средний удой через один осмотр после начала болезни снижается: мастит −468 кг, кетоз −439, гипокальциемия −358, ацидоз −318, паратуберкулёз −261, эндометрит −244, ламинит −219, копытная гниль −198, некробактериоз −139, отит −100.

Графики строит [src/plot_dynamics.py](src/plot_dynamics.py): `models/dynamics_milk_by_disease.png`, `models/dynamics_lameness_by_disease.png` (изменение за 3 осмотра до и 4 после начала болезни) и `models/dynamics_cow_examples.png` (удой отдельных коров с отметками болезней).

![Изменение удоя до и после болезни](models/dynamics_milk_by_disease.png)

Замечание: удой снижается и до начала болезни, потому что корова часто уже болела другой болезнью.

## 4.7. Прогноз на 2026 год

Скрипт [src/predict_2026.py](src/predict_2026.py) переобучает модели на всех данных (2023–2025) и считает риск на 01.01.2026 для каждого из 400 животных по его последнему известному осмотру. Результат — [data/predictions_2026.csv](data/predictions_2026.csv):

- `risk_probability`, `risk_level` — общий риск и уровень («Высокий» при вероятности не ниже 0.6);
- `risk_<болезнь>`, `level_<болезнь>` — риск и уровень по каждой из 13 болезней;
- `high_risk_diseases` — болезни с высоким риском у животного;
- `top_disease` — самая «подозрительная» болезнь (риск сильнее всего выше обычной частоты болезни).

Высокий общий риск у 200 животных из 400. Распределение рисков: `models/risk_distribution_2026.png`.

## 4.8. Выводы и ограничения

- Качество умеренное: общая модель ROC-AUC 0.74 на валидации и 0.75 на тесте; по болезням от 0.57 (авитаминоз) до 0.82 (ламинит).
- Болезни редкие, поэтому Precision по ним низкий (чаще 0.1–0.3). Модель лучше ранжирует животных по риску, чем «ставит диагноз», и пригодна для выбора животных на первоочередной осмотр.
- В тесте по большинству болезней всего 17–83 случая, оценки шумные. Отит и авитаминоз предсказываются почти на уровне случайного угадывания.
- Данные синтетические, связи заданы вручную, на реальных данных результаты будут другими.
- Пороги болезней подобраны на смеси сезонов, поэтому на дату прогноза (январь, зима) для бронхопневмонии высокий риск у 262 из 400 животных — это завышение.
- Семь редких болезней не моделируются.
